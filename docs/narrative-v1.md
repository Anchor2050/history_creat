# 通用叙事架构 V1：运行与设计

## 当前状态

这是可运行的多类型叙事实验架构，仍不是“已经能稳定产生优秀长篇”的完整成品。已连接世界状态、人物局部认知、组织规则、行动后果、反思、因果历史、叙事规划、正文与审阅。实际 Flash 实验暴露了行动停滞和审阅漏判；详见 [验证报告](validation-v1.md)。

统一使用 **deepseek-flash**。运行时没有 GPT 依赖；Jev 只有可替换判断接口，未接入真实 HTTP 服务。原版 `reverie/` 保留，新入口位于 `narrative/`；不是已经把旧 Persona/Storyteller 全部迁移完毕。

## 不依赖开发助手的独立运行

推荐入口是自动运行器。只需本地 Python 和 DeepSeek 配置；运行中不调用 GPT，不需要 Codex 为每轮选剧情、读稿或批准修订。

```powershell
python -m narrative.autorun --scenario narrative/scenarios/society.json --rounds 3 --steps-per-round 6 --max-calls 80 --output output/my-story
python -m narrative.autorun --output output/my-story --resume --max-calls 40
```

每轮依次执行行动、逐人物反思、叙事规划、正文、整体与逐句审阅。有具体问题时 DeepSeek 自行修订，默认最多两次；失败版本保留。达到修订上限后保存 needs_revision，再继续后续轮次，不将未通过的稿子冒充合格稿。人物反思会参与下一轮决策。

调用总上限覆盖当前进程全部轮次、审阅、修订及重试。API 或结构错误默认最多重试两次；遇到输出截断时，将单次输出额度翻倍，默认最高 32768（可用 `--max-output-ceiling` 配置），保持推理开启。更高额度可能增加 token 用量，重试仍计入总调用上限。预算不足立即保存，恢复时从未完成阶段继续。每次显式恢复是一个新的调用预算，累计用量见 job-usage.jsonl。恢复使用原任务保存的轮数、每轮步数和修订限额。

退出 Codex 不影响运行所需依赖，但必须让启动命令的 Python 进程继续运行；关闭该终端或关机后需要执行恢复命令。程序不是操作系统常驻服务。

输出根目录的 job.json 保存阶段；job-report.json 汇总完成轮数、各稿审阅状态、错误，以及等待、重复、拒绝和仅推进时间的事件数；round-0001 等目录包含逐版草稿、具体问题、逐句依据和最终可读稿。completed 仅表示指定轮次已跑完，稿件是否通过 DeepSeek 审阅要看 story_status。模型审阅仍会漏判，程序没有把 GPT 或人工读稿设为必要运行关卡。

## 手动分阶段运行

Python 3.11+，仅标准库。本地 `.env` 自动读取且被 Git 忽略；环境变量优先。文件采用 `DEEPSEEK_API_KEY=...`、`DEEPSEEK_MODEL=deepseek-flash`、`DEEPSEEK_BASE_URL=https://api.deepseek.com`。不需要执行原版的 uv sync。

```powershell
python -m unittest discover -s tests -v
python -m narrative.run --scenario narrative/scenarios/society.json --steps 6
python -m narrative.run --live --scenario narrative/scenarios/society.json --steps 6 --max-calls 19 --reflect --write-story
```

第一条运行测试；第二条是预先编写的机制演练轨迹，不产生调用费用；第三条由模型自行选择，预写轨迹不提供给角色或作家。

其他场景：`civilization.json`（延迟通信、错误信念、政策和能源），`mystery.json`（证据、调查、开门条件与筹码）。场景采用同一规则解释器；没有按题材更换程序。

## 恢复和分支

```powershell
python -m narrative.run --live --resume output/某次运行/checkpoint.json --branch alternative --steps 6 --max-calls 18 --write-story
python -m narrative.run --live --resume output/某次运行/checkpoint.json --story-only --max-calls 4
```

默认新建输出目录；分支记录父状态哈希与时刻。可重新叙述同一历史，不必重新推演。恢复保存轮次，包括此前被拒绝的提议，不会每次从第一个人物开始。不同分支只是允许不同后续，尚无自动大规模分支搜索。

## 运行闭环

1. 给当前人物建立私有视图，包含本人目标、信念及来源、关系、反思、已见事件。其他人物的私有状态不提供。
2. 程序列出当前可执行的候选动作；Flash 选择或提出对话，并给出简短自述动机。
3. 程序先验证规则，再调用可替换软判断。软判断只记录疑虑，不因“不够高效”否决合法人物选择。
4. 对世界副本执行；成功后整体提交，失败不改变任何世界事实。
5. 推进抽象时刻，处理消息送达、承诺到期、目标达成或失败，记录因果依赖、变化和各方可见通知。
6. 可选人物反思，只引用已见事件；保存在角色状态，恢复后参与下一次决策。它是角色自我解释，不等于全知真相。
7. 挑选状态变化较大的事件，补全因果前件，生成叙事顺序/视角，再生成正文、进行整体及逐句模型事实审阅；逐句结果必须覆盖全部文本单元并引用有效依据。审阅结果不等于人工验收。

## 数据与模块

| 模块 | 职责 |
|---|---|
| core.py | 事务式状态变化、人物视图、行动、组织、消息、承诺、目标、关系、快照 |
| rules.py | 可配置条件及角色权限；不执行配置中的任意脚本 |
| providers.py | Flash JSON 调用、次数上限、结束原因及 token 统计、可选判断回退 |
| story.py | 事件选择、因果闭包、初始状态和事实记录、叙事规划与审阅 |
| autorun.py | 独立多轮调度、反思、自动修订、阶段恢复和预算停止 |
| run.py | 候选动作、轮次、恢复/分支、反思、写作和导出 |
| scenarios/ | 初始世界、人物、资源、规则和离线演练脚本 |

状态事实与主张分开：事实有正向陈述和真值；每个角色的 claim 有他相信的真值和来源。`tell`、`send` 传播的是角色信念，可能是错的；`investigate` 根据场景设定取得真实证据。自由对话目前不会自动转为结构化信念。

组织包含成员、角色、权限、共同资源、政策选项及分配上限。普通成员可以 request 提交资源申请，负责人 allocate 分配；申请的完成状态与事件前因持续保留。需求不能直接读取对方私有目标，而必须通过可见申请/对话传播。

人物可选 name 字段用于中文视角标题；内部引用仍使用稳定 id。导出按场景标明视角。

长期目标可以是描述文字，也可以是可判定的条件（资源、物品、知道某事、公共标志、政策或地点），后者可设期限。文字目标由模型理解，不会自动冒充已完成。承诺履行/失信改变当事人的信任并留下经历；尚无完整人格演化模型。

## 动作与可配置规则

内置动作：wait、move、transfer、tell、send、speak、investigate、promise、request、allocate、enact、perform。

规则支持地点、条件、个人资源代价、组织权限、一次性使用，以及公共标志变化、生产资源、揭露证据。角色能看到公开的规则描述、地点和代价，看不到隐藏事实的真值或揭露内容。资源增加必须来自作者明确配置的生产规则；模型不能随口创造物品。

身份、初始角色名单、规则公开范围、组织内部公开账目等都是当前场景约定，不是对现实社会的完整模拟。所有成员现在可即时看到组织申请和政策，只有 send 动作模拟消息时延。

## 时间、因果与规模

一个成功动作推进一个抽象时刻；被拒绝的提议不推进世界时间。不是多人同步仿真，先后顺序会影响结果。物理移动只检查相邻地点，不模拟途中相遇。

人物主动引用的 causes 必须来自已观察事件。引擎另记录 dependencies：状态实体读写的前序写入及消息/承诺/申请来源。它是保守的依赖关系，可能包含弱相关前因，不等于文学上的充分因果证明。

快照含初始状态与全部事件，适合小场景，尚未优化长篇存储与上下文。人物视图仍可能随历史增长，不能据此宣称支持几十年或几百人物。

## 输出

- checkpoint.json：版本化初始与当前状态、事件、运行游标、分支元数据。
- attempts.jsonl：模型原始结构化提议、动机、判断及拒绝原因。不保存密钥或模型内部推理。
- history.md / summary.json：事件与状态摘要。
- manifest.json / manifest-history.jsonl：场景初始哈希、代码文件哈希、模型及调用上限。旧实验在该功能引入前没有此清单。
- usage.json / usage-history.jsonl：本次与历次请求数、token、结束原因。解析失败的响应也计入已报告用量。
- story-draft.json / story-draft.md：草稿、叙事规划与审阅。`model_review_passed` 仅表示模型自审通过，不能当成事实正确。

默认开启推理，单次输出最多 8,192 token（包含推理），无自动重试。调用上限按进程计算，不是固定金额；同目录恢复会追加用量历史。不要同时向同一输出目录运行多个进程。

## 距离完整设想的剩余工作

- 角色行动：减少空转，建立可检验的多步计划与持续意图，而不是靠要求“更精彩”的提示词。
- 人物：丰富关系变化、价值冲突、自我欺骗、长期记忆与人格演变；目前只有小部分机制。
- 世界：组织继承、内部博弈、制度变迁、物理/经济规则和多个时间尺度。
- 叙事：可靠区分角色信念与真相，控制揭示顺序，允许有根据的细节，防止润色改变历史。
- 评估：多随机种子、人物互换与规则消融、同预算基线、人工盲读。原版对照尚未运行，不能声称优于 StoryBox。
- 规模：增量事件存储、记忆检索、长篇分章、分支搜索、运行成本统计和可视化管理。

本次真实样本尚不足以证明文学质量；这些剩余项不能因为接口已经存在就勾选完成。


### 推理配置更新

默认使用 deepseek-flash，开启推理，单次输出上限 8192 tokens（包含推理）。此前关闭推理、2000 tokens 的实验配置仅属于历史验证记录。可用 `--no-thinking` 显式关闭，或用 `--max-output-tokens` 调整上限；调用次数仍受 `--max-calls` 限制。2026-10-11 一次真实调用正常结束，返回正确答案，使用 68 个推理 tokens、总计 171 tokens。此检查只验证推理接口，不代表叙事质量验收。

配置依据：[DeepSeek 官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)说明思考开关、max_tokens 与 length 结束原因；本程序选择比接口最高值更小的运行上限。
