# 纯 ChatGPT 世界驱动与写作

状态：实验分支 `chatgpt/pure-chat-driver`。该路径不调用 DeepSeek，也不调用 GPT API；模型生成发生在已连接仓库/执行工具的 ChatGPT 对话中。

## 边界

ChatGPT 可以承担人物决策、章节写作、事实审阅、文学审阅和修订，但不能直接修改规则事实来迁就故事。资金、时间、权限、同意、审批、已发生历史与读者记忆仍由 Python 状态机约束。`Exchange.receive` 只表示收到了模型回复；只有规则引擎接受并提交后才能成为世界事实。

同一聊天扮演多个角色不等于独立心智。人物任务只导出该人物的最小可见上下文，以降低信息串漏；验收报告必须保留这一限制。

## 推进闭环

1. `load_beijing()` 编译北京初态，建立 `World` 和 `ChatRun`。
2. 对本周人物逐一生成 `decision_task(actor)`。任务带世界状态哈希和最小人物上下文。
3. ChatGPT 只依据任务包作答。回复经 `receive` 做任务身份、哈希和过期检查。
4. 程序将结构化动作逐项送入 `World`/`Characters`；越权、超时、余额不足、缺少同意等动作失败并留下验证结果。收到回复本身不推进世界。
5. 世界事件形成后，选择有叙事价值且有来源的事件生成 `chapter_task`。正文只能使用这些事件和已发布 reader memory。
6. 先做事实审阅，再做文学审阅。文学审阅覆盖人物声音、具体性、节奏与留白、体察与自主性、意象；若未通过，保留草稿并修订。
7. 只有事实审阅和文学审阅都通过的章节才能进入 `ReaderMemory.publish`。
8. 每个任务边界和章节边界保存 `ChatRun.checkpoint()`。新聊天从 checkpoint 恢复，不需要旧聊天全文。

## 第一阶段真实实验

先跑北京故事第 1 周，不追求强行制造戏剧性。八名人物各有一次常规决策机会；允许选择等待、拒绝、说明边界、工作、求助或协商。随后写第一章并保留事实审阅、文学审阅和至少一次有需要时的修订。

第一章成功后保存 checkpoint；第二阶段应从保存状态恢复，继续下一周和第二章。只有真正从仓库保存点重新接管时，才把它记作跨聊天恢复证据。

## 真实性要求

- 不把测试中的模拟 reply 写成真实 ChatGPT 世界运行。
- 不把 ChatGPT 对正文的自审称作独立模型审阅。
- 不虚构 token/API 成本；本路径 API key 使用量为零，聊天平台内部用量若不可观测就标记不可观测。
- GitHub 没有自动测试时，只能写“测试已提交”，不能写“远端测试通过”。
- DeepSeek 基线和四项对照仍是原 SMART 目标的独立验收项，本实验不能替代它们。
