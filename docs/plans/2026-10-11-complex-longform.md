# Complex Long-form Narrative Implementation Plan

> **For Codex:** 使用已授权的 executing-plans 流程逐步执行。用户要求持续推进，不在批次之间重复请求开工许可。

**Goal:** 为复杂长篇叙事建立人物、制度、时间、记忆与文学表达的可运行条件，支持 DeepSeek 独立运行及 ChatGPT 聊天接管，以北京博士生活连续章节及对照检验。

**Architecture:** 保留 V1 作为兼容基线。在 narrative/longform 中建立日历化世界、事务账本、持续人物与跨章叙事状态。世界事实、人物认知、读者所知和文学表达分层保存；决策、写作、审阅与修订通过可替换驱动接口完成；DeepSeek 与聊天助手共用程序强制的权限、时间、资源、引用及恢复规则。

**Tech Stack:** Python 标准库；现有 DeepSeek Flash JSON 接口与调用预算；JSON 快照/事件/章节版本；unittest。

## 完成条件

不是新增几个模块就完成：北京 8 人、3 组织，运行 6 周、48 个常规决策机会及最多 2 个条件响应，生成至少 6 章接续正文，保留失败与修订；后续继续运行仍能引用早先承诺和读者记忆。验证日历、时间/钱、审批、人物变化、信息隔离、多条未解决线索。以独立对照检验现金、分工制度、表达倾向和移除感情线的作用。DeepSeek 路径不得由开发助手代替角色选剧情或修改正文补过验收；聊天路径允许助手承担这些工作，但必须独立标注来源并接受相同核验。

章节长度按内容选择，首轮目标每章约 1000—2000 汉字，不用字数冒充文学性。长篇规模与稳定文学质量仍需更长期验证；本轮要证明支撑条件及连续运作，不能声称已经产生名作。

## Task 1：创作契约与长期记忆

- Create: narrative/longform/literary.py；tests/test_longform_literary.py；docs/longform-poetics.md。
- 测试：未知/未来事件不能作为章节依据；读者记忆不能提前知道作者计划；修订不能重复提交同一章；世界事实不因细节和叙述解释被回填；未解决线索有出处与状态。
- 实现：读者账本、章节元数据、带出处的线索与意象、文学表达许可。允许有根据的场景细节、节奏、留白、比喻与局部体验，不允许改变关键行动、权限、钱、承诺或同意。
- Run: python -m unittest discover -s tests -p test_longform_literary.py；先失败，再实现，再通过。

## Task 2：日历与双重约束账本

- Create: narrative/longform/ledger.py；tests/test_longform_ledger.py。
- 测试：跨周任务占未来额度、失败不改账、时间不能重叠、收入有来源、双边钱款守恒、日期到期、保存恢复幂等。
- 实现：具名账户、日历工作预订、资金转移、计划外延迟处理；不以金钱或工时直接判论文合格。

## Task 3：北京场景编译与可检查产物

- Create: narrative/longform/scenarios.py；narrative/longform/world.py；tests/test_longform_world.py。
- 将 docs/scenarios/beijing-doctoral-initial-v1.json 编译为可运行初态，显式补全尚未有值的经费/资料/材料版本与权限。改变设定时写迁移说明，不静默改变人物的拒绝、身份或资源。
- 任务、交付、评阅意见、核验、提交是分离对象；导师/行政/项目方权限有限，规则可配置。合规互助、分工协商、说明边界、拒绝新增义务均有具体对象与后果。
- 测试：多级审批、公司付款、任务增补须确认、宿舍不同资格、截止后的下一批路径、帮助不生成恋爱权利。

## Task 4：持续人物与局部信息

- Create: narrative/longform/characters.py；tests/test_longform_characters.py。
- 同周信息冻结；持久化两周计划、优先次序、承诺、分领域信任、边界、不确定判断与反思证据。
- 模型提议改变自己目标与计划必须给出已见经历和受影响承诺；不允许全知解释他人、不允许自动重写别人的同意。
- 测试：未知告白/余额隔离；计划受挫反馈；下一轮使用自己的反思；已发生的好意有代价与记忆，不奖励道德分。

## Task 5：连续章节写作与文学修订

- Create: narrative/longform/chapters.py；tests/test_longform_chapters.py。
- 挑选本期变化及必要前因，读入已写章节摘要、已揭示信息、未解决线索和意象。规划本章叙事焦点、场景与概述比例、揭示次序、与前章关系。
- 事实审阅与文学审阅分别进行。后者检查人物声音、具体性、过度解释、节奏、廉价煽情、对他人的体察、意象是否有生活依据；给具体改写任务，不输出统一“善美分”。
- 修订保留版本，已发布章不静默改动；失败草稿不得推进正式读者记忆。允许文学表达，不让每个比喻都必须等价于事件日志。

## Task 6：独立有界调度与恢复

- Create: narrative/longform/run.py；tests/test_longform_run.py。
- 周初人物私有视图 → 自主决定与排期 → 事件推进 → 通知/反思/计划更新 → 连续章节 → 独立审阅修订 → 下周。
- 复用 V1 的 DeepSeek 预算与错误处理经验，持久化每个已完成阶段；API、格式、截断、预算耗尽均能有限处理并恢复。
- 新入口计划：python -m narrative.longform.run --scenario beijing --weeks 6 --max-calls 240 --output output/beijing-longform。
- 此命令在对应模块完成前不是可用入口。

## Task 7：分支与对照

- Create: narrative/longform/experiments.py；tests/test_longform_experiments.py。
- 固定外部事件表与初态哈希，支持现金缓冲、劳动规则、表达方式与感情线消融。模型输出非确定，报告单次分支证据的局限。
- 对照检查约束是否改变可选行动与实际选择；记录无差异和失败，不强行生成不同结局。未消费完的来源预算、时间、信息始终守恒。

## Task 8：真实验证与中文交付

- Create: docs/longform-running.md；docs/longform-validation.md；更新 README 与设定实现状态。
- 完成离线检查后，第一阶段真实短闭环最多 80 次调用；确认链路后主场景六周最多 240 次。对照先用与主场景前两周匹配的窗口，每支最多 80 次；扩大前根据真实用量报告收敛方案。每一阶段限额单独记录，不自动无限重试。
- 验收至少包括：主场景连续六章；旧经历影响后续选择的记录；未解决事项延续；制度和资源约束产生可解释张力；有成本的照顾、守信或合作有行动空间与后果；文学修订保留具体前后差异。
- 如果生成中没有体现善或美，先检查可执行合作机制、叙事焦点、具体性与修订任务，不塞入人物突然牺牲或大团圆。若对照未显示差异，报告并继续诊断。
- 密钥本地忽略，原版与 V1 保留；代码完成后才提交，真实验证结果不得伪装成手写样本。
