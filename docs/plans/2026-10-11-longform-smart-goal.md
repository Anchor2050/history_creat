# SMART 长篇叙事目标

状态：已写入本聊天的 active goal。设定时间：2026-10-11。以下时限均为北京时间，故事内部仍从 2026-03-02 开始，两种时间不可混淆。

## S：明确性

基于北京博士生活的 8 人、3 组织，交付驱动者可替换的长篇叙事实验架构：支持 DeepSeek Flash 推理模式独立运行，也支持 ChatGPT 聊天助手通过当前环境的文件/执行工具自行推进，聊天模式不需要 DeepSeek 或 GPT API 密钥。范围包括日历与跨期任务、个人时间/资金、多级审批、局部认知、持续计划与人物关系、累积后果、跨章规划/读者记忆、分开的事实审阅与文学审阅、自动修订与断点恢复。

文学契约见 ../longform-poetics.md：真实、善与美须有行动和表达空间；重点关注体谅、守信、公平协商、互助、自主性、具体日常与形式，不采用道德总分、指定情侣或强制善终。

## M：衡量性

1. 基线 6 个故事周，48 次常规决策机会和最多 2 次有依据的响应；至少 6 章。从保存点续跑 2 周，再追加至少 2 章。合计不少于 8000 汉字。字数证明持续写作，不证明文学质量；保留失败、修订、用量及状态。
2. 测试覆盖资金守恒、时间不重叠、权限/审批、信息隔离、拒绝边界、跨期后果、经历影响计划、读者记忆、预算和恢复；硬规则测试全部通过。
3. 四项对照：现金缓冲、劳动分配制度、表达倾向、感情线消融。各与基线相同前两周及外部事件表比较；报告差异或无差异，不伪造结局分化，不把一次分支视为因果证明。
4. 至少三条跨章未解决事项、两条经历到计划变化的证据链。选三个实际场景做独立文学审阅，分别检查人物声音、具体性、节奏与留白、体察与自主性、意象呼应；意见须指向具体文本。至少保留一次根据文学意见自动修订的前后版本。
5. 专门评估有成本的互助、守信或公平协商是否发生、如何被表达；缺失要如实诊断，不能靠口号、廉价煽情或强塞牺牲制造通过。
6. 交付启动/恢复命令、中文说明、连续正文、逐项验收报告及未证明边界。DeepSeek 模式不能依赖 GPT 人工改稿或批准；ChatGPT 模式允许聊天助手直接承担决策、写作、审阅与修订，但仍通过同一规则引擎核验，不能绕过状态约束。两种模式的验证记录须分别标识，不互相冒充。

## A：可实现性

本轮交付“支撑复杂长篇的条件与八章连续运作”，不保证名作或百万字稳定性。先做规则与集成验证，再做真实调用。

真实请求总上限 720 次：短闭环 80，六周基线 240，保存恢复后的两周 80，四项对照各 80。所有失败和重试计入对应阶段；不得因未通过而悄悄增加额度。此上限不是固定人民币价格保证，实际 token 用量另记。达到额度时保存未完成状态并报告。

## R：相关性

所有新增模块与验证都服务于人物驱动、时代与制度张力、真善美和连续叙事。保留当前北京设定、原版及 V1 对照，不转向无关 UI 或另换简单题材来替代目标。

## 2026-10-11 补充：聊天助手与 GitHub 兼容验收

这是用户对 active goal 的追加要求，与以上 SMART 条件共同生效。工具中原目标的“仅用 DeepSeek”应解释为 DeepSeek 路径可独立运行，不再限制整个项目只有一种驱动者。原期限、八章基线、四项对照和 API 总预算不变；若新增范围影响期限，如实报告，不静默缩减验收。

7. 在不配置任何模型 API 密钥的环境中，由聊天助手实际完成至少两周推进和两章生成；第一章保存后，在不依赖旧聊天全文的恢复上下文中继续第二章。提交事件、人物计划、读者记忆、正文、审阅和修订证据；必须明确是否真正换了会话，只有重建上下文的测试不得冒充换会话。此项是附加兼容性证据，不能替代 DeepSeek 八章验收。
8. 同一保存点可切换驱动者；拒绝过期状态的回复、不同内容的重复提交与绕过规则的修改，接受相同回复的幂等重试。模拟回复只能验证协议，不能冒充真实 ChatGPT 执行结果。
9. GitHub 默认无定时任务、无轮询、无逐行动提交。两章兼容性实验以不超过 12 次远端读取、4 次批量写入尝试为项目上限，失败与重试也计数；不触发 Actions。记录实际请求数、写入批次和 Actions 运行次数，不将项目上限当成 GitHub 平台额度或费用保证。权限不足时保留本地可提交成果，明确未完成远端同步验收。
10. 聊天接管入口须说明如何读取当前进度、取得最小任务包、返回结果、执行核验、保存和恢复；密钥、环境变量、完整聊天记录与临时输出不进入同步包。没有执行/写权限的环境应准确报告能力缺口，不宣称文本推演已经落盘。
