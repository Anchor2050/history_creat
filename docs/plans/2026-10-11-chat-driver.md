# ChatGPT 聊天接管与 DeepSeek 双驱动设计

日期：2026-10-11。状态：设计已纳入 SMART 目标，尚未实现或完成远端验证。

## 用户要的运行方式

项目可以托管 GitHub。ChatGPT 聊天助手读取项目进度，在当前聊天环境中自行处理角色决策、章节写作、审稿、修订和推进，通过可用执行工具运行规则程序并保存结果。不要求用户购买 GPT API，也不要求配置 DeepSeek。DeepSeek Flash 仍是可独立运行的另一条路径，Jev 保持可选。

“兼容聊天”不是生成提示词后让用户反复复制粘贴。具备执行和写权限时，助手应自己完成任务交换和阶段保存。GitHub 用作代码与阶段成果的持久存储；计算在当前已授权执行环境发生。能力取决于具体聊天所连接的工具，仓库文件无法凭空赋予执行、写入或后台常驻能力。

## 共用规则，替换生成者

世界规则、资金/时间账本、角色知识、关系边界、审批、事件、章节记忆和存档均与模型供应商无关。推进器先持久化一个待办任务，再由驱动者作答，最后统一校验并保存。

- DeepSeek 驱动：调用现有 Flash JSON 接口，并记调用量、失败和预算。
- 聊天驱动：导出当前待办任务，助手直接生成回复并调用接收入口；不初始化 API 客户端、不读取密钥、不假造 API 用量。
- 可选判断器：仅提供有来源的建议，不能改写规则或成为必需依赖。

不采用 GitHub Actions 逐步调用模型；不把整个世界反复塞入聊天；不维护两套剧情引擎。

## 持久化任务协议

计划字段：协议版本、运行 ID、任务 ID、阶段、当前状态摘要哈希、输入哈希、角色/审阅身份、最小上下文、输出结构、允许引用的证据 ID。回复必须引用任务 ID 和相同状态/输入哈希，携带结构化结果与驱动来源。

人物任务只能包含该人物可知的信息。写作任务可取得所选事件及叙事所需上下文，读者记忆只收已发布内容。模型扮演多个角色的聊天并不构成对隐藏信息的密码学隔离：最小任务包和输出校验降低泄漏风险，仍须在报告中保留这一局限；不能宣称扮演角色就等于真正独立心智。

任务生命周期：pending → received → validated → committed。格式不合格的回复保存诊断，未通过世界规则的动作不能成为事实。已提交同一回复重试返回原回执；不同回复复用同一任务 ID 必须拒绝；旧存档产生的回复不能覆盖新状态。保存采用事务或原子文件替换，不能出现资金已扣但阶段指针未更新的半提交。

任务校验、规则接受、章节发布是不同结果。不能把“拿到回复”当作“世界行动成功”，也不能把“写完正文”当作“正文审阅通过”。切换驱动者发生在已保存任务边界，保留已有草稿、失败、记忆和证据，不重新生成已提交行动。

## ChatGPT 自行推进流程（待实现入口）

1. 读取接管说明、当前阶段摘要与最新存档索引；核对版本、哈希、未完成任务和预算。
2. 在执行环境加载代码与存档，取得当前任务包。
3. 在聊天中按任务身份生成结果，通过接收入口提交，读取规则回执。
4. 根据回执继续任务；事实审阅与文学审阅分开调用/分开记录，同一聊天中的两遍审阅不伪称来自独立模型或独立会话。
5. 一章完成或达到本次工作上限时保存检查点，更新简短恢复说明；阶段同步到仓库。
6. 下次聊天读取该包继续，无需用户重讲故事或粘贴全部旧对话。

以上是实施约定，当前没有可供用户运行的聊天模式命令。后续文档必须只列已经测试过的实际入口。

## 控制 GitHub 操作量

默认不添加 schedule/push 触发的工作流、不轮询仓库或任务状态、不把单个人物动作写成一次提交、不将 Issues 当消息队列。先读当前引用与阶段索引，在当前环境集中计算，按章或工作批次一起同步。

计划同步包采用显式文件白名单：版本化的运行存档、增量事件、章节与评审、运行来源/用量、恢复说明及校验清单。输出目录当前被 Git 忽略，不能靠强制添加整个 output 来同步；须另行实现最小导出包，排除环境文件、密钥、完整聊天记录及无关日志。保留必要失败版本与审阅证据，避免重复大文件。

写回前确认远端基础版本未变化；冲突时保存本地成果并报告，不强制覆盖。达到本次远端操作上限则停止同步尝试，保留可恢复状态。测试应同时记录项目层批次与工具可见的底层请求数；无法观察工具内部请求时明确“不可观测”，不得把一条批量工具调用直接声称为一次 GitHub API 请求。

## 验收与边界

SMART 补充要求两周、两章真实聊天推进，跨保存点恢复，零模型 API 密钥，统一规则检查，过期/重复回复和跨驱动切换测试。另以实际权限完成一次仓库阶段同步；若没有权限，记录未完成，不能用本地文件存在代替远端成功。

原 DeepSeek 八章、对照实验与 720 次请求上限仍保留。两种驱动的质量与成本分别记账；聊天模式不记虚假的零 token 成本，标注聊天平台用量是否可观测。ChatGPT 输出不是独立文学质量证明，也不能代替硬规则测试。
