# 通用叙事架构 V1 执行计划

目标：从最小因果原型推进到可配置、多类型场景可运行的叙事实验系统。不是保证生成名作；文学质量需实读。

## 验收里程碑

1. 模型链：修复推理耗尽输出、记录失败用量与结束原因，默认 DeepSeek，Jev 接口可替换。真实生成结构化行动和草稿成功。
2. 世界与人物：延迟信息、可错误的主张及来源、调查纠错、对话、长期目标与事件引发的信任变化。角色视图不能泄露全知信息。
3. 组织与规则：组织成员、角色权限、共享资源、可配置行动规则（明确前置条件、代价、效果），资源守恒和权限检查。
4. 历史：自动状态依赖与人物引用分别记录，持续承诺/期限，反思与目标变化，保存恢复、分支元数据。
5. 创作：按变化选择事件并补全因果前件，组织叙事视角/揭示顺序，生成引用事件的场景草稿，再做有记录的事实审阅。不得静默把新情节回填成事实。
6. 验证：社会资源分配、文明信息与科研、封闭规则谜局三个原创小场景。规则测试 + 程序脚本演练 + 预算受控真实模型验证。输出可阅读报告，列出无聊/重复/幻觉与覆盖边界。

## 文件与步骤

- tests/test_provider_v2.py → narrative/providers.py：先测截断用量、诊断与上限，再修复。当前默认单次 8,192 token，开启推理，无自动重试；2,000 token / 关闭推理为已保留的早期实验。
- tests/test_world_v2.py → narrative/core.py, narrative/rules.py：测试局部认知、消息时延、权限、资源、自动因果、长期目标和关系后果；再实现兼容 V1 快照的 V2。
- tests/test_story.py → narrative/story.py：事件选择与因果闭包、引用校验、审阅失败保留草稿。
- tests/test_run.py/integration → narrative/run.py：场景化动作菜单、状态恢复与分支、完整导出、配置调用上限。
- narrative/scenarios/*.json：三个机制不同的场景，内含可执行的离线演练轨迹作为世界规则验收；真实运行由模型决定，不使用轨迹。
- docs/narrative-v1.md, docs/validation-v1.md, README.md：能力矩阵、真实样本、运行配置与后续差距。

## 实际模型预算与边界

本轮计划先每种场景 6 个行动（提出与判断最多 12 次）加叙事/审阅，合计不超过 60 次新请求，必要修复复验在总计 80 次内。每次运行有独立调用上限；记录 token，不宣称固定人民币成本。密钥仅本地 .env，不进入版本控制、输出或报告。

先规则测试，再真实调用；没有证据不把目标标为完成。暂不建立 Web UI、视频/漫画生成、分布式调度、训练模型或大规模自动采样。原版 reverie/ 不改动，作为后续对照，但不把尚未运行原版宣称为效果胜出。


后续推理复验：社会场景最多 24 次；文明与谜局各最多 16 次；既有历史逐句审阅最多 2 次。总上限 58 次新增请求，逐次记录用量，不沿用早期关闭推理的结论。
