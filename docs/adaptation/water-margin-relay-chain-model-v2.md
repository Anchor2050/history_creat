# 《水浒传》式接力叙事模型 v2

状态：`adaptation_only`，只用于小说改编层；不改写历史账本。

## 纠偏

前一版把《水浒传》的“人物出场”误读成：给每个核心人物分别设计一场高质量登场戏，然后依次展示。

这仍然是人物名单驱动。

《水浒传》真正值得借鉴的是**故事传棒**：先有一桩正在发生的事，这桩事逼出一个人；这个人的行动把故事带到新的地方、关系或麻烦中，于是另一个人自然出现。人物不是因为“轮到他介绍”而出现，而是因为故事已经走到他那里。

因此本项目废止“先把六个核心人物逐个登场完毕”的任务。

## 核心原则：事带人，人带事

叙事单位不是“人物介绍章”，而是：

`正在发生的事件 -> 人物被卷入 -> 人物行动改变局面/信息/关系 -> 产生下一处去向 -> 在下一处遇见新人物或旧人物的新面貌`

新人物只有在这个链条需要他时才进入。

一个核心人物可以很晚才进入小说。核心地位不等于早登场。

## 与《千面英雄》的分工

- **Water Margin relay** 决定：镜头现在跟谁、下一步为什么走到另一个人那里。
- **Campbell arc** 决定：某个人一旦进入以后，他长期会经历怎样的召唤、试炼、阴影、转化和不完整返回。
- **negative space** 决定：这些变化在正文里只露多少。

严禁让 Campbell 人物弧反过来制造轮流出场结构。

## 开篇阶段硬规则

1. 前 3–5 章不要求覆盖六个核心人物。
2. 一章新增可记忆姓名原则上不超过 1–2 个。
3. 章节结尾优先留下一个**去向**，而非一个主题：某条消息、一次约见、一个人要去的地方、一件尚未办完的事。
4. 下一章优先接住这个去向；允许时间跳跃，但必须能回答“为什么镜头现在到了这里”。
5. 连接可以是：直接因果、人物同行、已有关系、被转交的任务、被提及后实际出现的人、公开程序的下一阶段。
6. 仅有相同主题、相似选择、相同年代，不算剧情连接。
7. 群像关系可以分叉：一条线暂时跟 A，另一条线稍后从 A 遇到的人 B 处分出去；允许数章后再汇合。
8. 非核心人物可以短暂承担“传棒者”甚至一整场 POV；世界不为核心六人让路。

## 人物第一次进入时

人物仍然采用“以事出人”：

- 他先做什么；
- 别人怎样对待他；
- 他在当前权力位置能做什么、做不了什么；
- 只露一个最需要读者记住的矛盾。

但这不意味着每个人都要拥有独立的‘登场章’。

## 链条审计

每安排下一章前必须回答：

1. 上一章留下了什么具体去向？
2. 为什么镜头会从上一个人移动到这个人？
3. 如果删掉这个人物的名字，只保留功能，故事是否仍自然需要这个角色？
4. 这次相遇是否有既有关系/公开场景/合理介绍路径？
5. 新人物进来以后，他自己的目标是否立刻存在，而非只服务于前一个人物？
6. 本章结束后，故事又被推向哪里？

如果只能回答“因为该介绍下一个主角了”，本章不得起草。

## 推荐结构形态

不是：

`宋楠登场 -> 周野登场 -> 罗诚登场 -> 唐雨登场 -> 何欣登场 -> 高原登场`

而是类似：

`一桩求职/工作事件 -> 当事人去找一个已知的人 -> 这个人手头还有另一件事/另一段关系 -> 新人物因那件事进入 -> 原线暂时退场 -> 新线产生自己的后果 -> 数章后在真实关系节点重新碰到旧线`

读者追的是“接下来这件事会把我们带到哪儿”，人物群像由故事自然扩大。

## 对已有素材的处理

现有 Zhou / Song / Luo entrance probes 保留为**人物场景素材**，不再代表前三章顺序。

现有 Ch1–Ch6 继续作为历史事实、对白、场面和长期弧光素材库，不拥有出版版章节编号。

下一步先建立一个 `opening relay graph`，只选一条能自然走 4–6 个节点的事件链，再写连续章节。不要先完成剩余三名核心人物的独立出场测试。
