# 嵌套英雄旅程与子故事模型 v1

本文件属于 adaptation-only 设计层，不修改 2026–2035 历史 ledger。

## 一、总体结构：不是一个英雄，而是一组同时与世界交手的人

本作品采用三层叙事结构：

1. **主弧（long arc）**：六名核心人物跨 2026–2035 的长期英雄旅程；
2. **子故事（substory）**：某一人物在数月到数年内面对一个相对独立的问题；
3. **过客微弧（guest micro-arc）**：同事、领导、学生、家人、项目伙伴、竞争者、办事人员、朋友等只出现一场到数场，但仍有自己的目标、位置与变化。

六名核心人物并非彼此生活和工作的核心。他们是同代群像中的弱连接与互为镜像者：各自在自己的阵地与世界互动、理解世界、被世界塑造，也局部改变世界。

因此，大量真正改变他们的角色来自主群像之外。

---

## 二、主弧继续以 Campbell / 《千面英雄》为深层骨架

核心人物仍使用分布式英雄旅程：

- ordinary world
- call
- refusal / hesitation
- threshold
- trials
- descent / shadow exposure
- insight / transformation
- return
- post-return consequence

这些功能不必完整、不必等距，也不直接出现在正文中。

人物弧光的重点是：

> 他经历世界以后，仍然保留什么稳定内核；什么特质被重新调节；他带回了什么能力、边界、伤痕或判断；这些新东西又制造了哪些后续代价。

---

## 三、子故事：主弧中的局部完整世界

每个子故事至少包含以下六项：

1. **局部 ordinary world**：事情开始前人物已经习惯的状态；
2. **局部 call**：出现一个需要回应的新问题；
3. **阻力/门槛**：制度、能力、关系、资源、时间或本人阴影；
4. **互动链**：必须与具体他人/组织发生交互，而不是全靠内心独白；
5. **局部转化**：得到一个新判断、失败证据、关系变化、边界或技能；
6. **残余代价**：子故事结束以后仍留下什么没解决。

一个子故事可以失败，可以没有“成长”，也可以只是更清楚地发现某条路不值得继续。

### 示例

**周野培养第二判断者**是一个子故事：
- ordinary：复杂异常长期由周野判断；
- call：房产锁定与专家单点叠加；
- threshold：必须让别人真正做判断，而不只是看文档；
- trial：同事先只能处理常见分支；
- transformation：周野接受部分不同判断也可以成立；
- residual cost：最稀有边界情况仍依赖本人。

## 四、过客微弧：出现很短，也必须像人

任何有名字、承担真实冲突功能的过客，都不能只是一块剧情工具。

### 最低人物要求

每个过客至少记录：

- `current_role`：当时的真实/虚构职位；
- `current_goal`：这一阶段他真正想得到什么；
- `pressure`：当前最直接的压力；
- `virtue`：一个帮助他活到现在的优点；
- `shadow`：这个优点在当前情境中的过量风险；
- `power_position`：相对主人公是更强、更弱、平级还是交叉权力；
- `information_set`：他知道什么、不知道什么；
- `micro_hero_stage`：这一场/几场中他自己处在 call、trial、refusal、threshold、return 等哪个位置；
- `interaction_mode_with_protagonist`：mentor / ally / guardian / shadow / rival / mirror / dependent / client / authority 等；
- `what_changes_for_guest`：和主人公交互后，他自己有无一点变化；可以为空。

### 最小原则

过客可以只出现三页，但读者应隐约感觉：

> 他进场以前已经有生活，离场以后也会继续生活。

---

## 五、过客不等于好人，也不等于坏人

局部反派必须满足：

1. 他在保护一种可以理解的价值；
2. 他拥有有限而真实的信息集；
3. 他的利益和主人公不完全一致；
4. 他做出的决定可能局部合理；
5. 决定的外部成本由另一个人承担；
6. 换到另一条故事线，他可能很值得尊重。

例如：

- 招聘负责人拒绝一个高学历候选人，可能因为岗位需要真实学生工作证据；
- 项目经理拒绝给宋楠真实数据，可能因为权限和预算；
- 导师要求砍题，可能是在保护学生时间，也可能过度放大自己的风险偏好；
- 年轻同事不愿继续依赖周野，可能显得“不听话”，但也可能是在争取判断权。

## 六、弱关系群像：不强行把六个人绑成“六人帮”

核心六人可以：

- 数月不联系；
- 只在群里说一句；
- 偶尔吃饭；
- 只在某类问题上想到对方；
- 通过别人的近况反观自己；
- 在关键年份互相成为镜子，但不互相解决问题。

他们共同对抗的不是同一个具体敌人，而是各自在自己的社会位置上面对：

- 制度；
- 时间；
- 能力定价；
- 城市与住房；
- 权力；
- 家庭距离；
- 专业标准；
- 自己的性格阴影。

群像统一性来自“时代问题”和重复结构，不来自强行的共同任务。

## 七、允许按剧情需要反向生成小角色

改编层允许以下工作流：

### Step 1：先发现场景缺口

例如：
- 周野需要一个真正接他异常判断的年轻同事；
- 宋楠换岗后需要一位产品/医学侧合作人；
- 何欣做内部职责增量时需要一位直接领导或跨部门同事；
- 罗诚第二次迁移时需要一位新平台上的项目负责人。

### Step 2：生成 adaptation-only 角色假设

只生成完成场景所需的最小履历，不补完整传记。

### Step 3：反向合理性审查

至少检查：

1. **时间可行性**：这个人在当年是否可能处于此年龄/职位/资历？
2. **制度可行性**：他是否真的有权限做出场景中的决定？
3. **专业可行性**：他的训练是否支持他说/做这些事？
4. **关系可行性**：他为何与主人公发生这次交叉？
5. **信息可行性**：他是否知道这些信息？
6. **利益可行性**：他的选择对自己有什么收益与风险？
7. **人格可行性**：行为是否能从其优点、阴影、压力和位置共同解释？
8. **时代可行性**：行为是否符合当年组织、行业和社会环境？

如果审查失败，修改角色或场景；不得为保护场景而硬解释。

### Step 4：只进入 adaptation layer

这些新增角色和细节默认不回写历史 ledger。

## 八、过客角色的微型 Campbell 弧

不要求完整 12/17 阶段。

建议使用 3–5 步极简弧：

### A. Position → Pressure → Choice

适合只出现一场的制度角色。

### B. Ordinary → Call → Boundary → Residue

适合领导、招聘者、项目负责人。

### C. Desire → Friction → Misjudgment → Small Correction

适合合作伙伴、同事、朋友。

### D. Competence → Overreach → Cost → Recalibration

适合高能力配角。

### E. Need → Refusal → Negotiation → Partial Gain

适合弱势位置角色。

微弧的作用不是抢主角戏，而是使交互具有双向性。

---

## 九、子故事与主弧的连接规则

每个子故事至少承担以下一种功能：

- 暴露主人公一个稳定内核；
- 暴露一个优点的阴影；
- 改变主人公对世界的模型；
- 改变主人公在组织中的真实位置；
- 产生延迟后果；
- 让主人公成为别人故事里的阻力/帮助者；
- 提供普通生活和情绪反差；
- 显示同一时代问题在别人的人生里长成不同形状。

如果一个子故事只负责“解释主题”，应删除或重做。

---

## 十、Storyteller 后续工作规则

Storyteller 在每个核心场景进入 prose probe 前，需要决定：

1. 这是主弧节点还是子故事节点？
2. 是否需要新增过客？
3. 已有角色能否自然承担此功能？优先复用已有真实关系，不为热闹增人。
4. 若新增，生成最小 guest dossier；
5. 给 guest 一个简短 micro-hero arc；
6. 运行 reverse plausibility audit；
7. 通过后再生成 disposable prose。

## 十一、核心原则

世界不是围着六个主角转的。

每个人都只看见自己生活的一小块；那些与他们擦肩、阻拦、帮助、误解、合作的人，也都在自己的故事里向前走。

好的群像要让读者感觉：镜头移开以后，世界仍然在运行。
